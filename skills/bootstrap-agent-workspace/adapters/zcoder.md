# ZCoder 适配器

## 定位

“ZCoder”可能指不同项目、CLI 或基于 Claude Code 的编排方案，目前不能假定存在统一的自动加载标准。

## 检测信号

- 当前客户端或用户明确声明具体 ZCoder 产品与版本
- 项目存在该实现特有配置目录
- 已有规则入口中明确标注 ZCoder

仅凭目录名或模糊名称不得自动判定。

## 必问项

无法从运行时证据确定时，必须询问：

1. 使用的是哪个 ZCoder 实现、版本或项目链接？
2. 它自动加载项目中的哪个目录或文件？
3. 是否兼容 `AGENTS.md` 或 `CLAUDE.md`？
4. 入口支持引用其他 Markdown，还是必须内嵌关键规则？

## 生成策略

1. 本适配器不创建任何公共核心文档。
2. 若确认兼容 `AGENTS.md`，仅在该文件已存在或本次核心流程将生成时复用；否则跳过项目规则入口。
3. 若确认基于 Claude Code，使用 Claude Code 适配器，但仍受 `available_artifacts` 门禁约束；登记别名 `ZCoder (Claude-based)`。
4. 若有专属入口且确认支持引用，只生成 P0 薄索引，并只引用 `available_artifacts`；P1 列路径和条件，P2 保持按需读取。
5. 若入口不支持引用，只内嵌最小安全红线、实际存在的项目事实源路径和按需读取指令；没有可用事实源时不生成空壳入口。
6. 未确认条件规则或自动发现能力时，不映射为原生分级功能；采用薄入口 + 路径索引，并确保同一事实源不被重复自动加载。
7. `AGENTS.md` 可用时将确认结果写入工具适配表；否则只在本次执行结果中报告，不得为登记状态创建它。

## 校验

- 未确认标准前状态必须为 `pending-confirmation`。
- 不把网络搜索中名称相近的项目当作用户使用的实现。
- 入口路径、加载方式和冲突优先级均有证据。
- 实际生成的入口只引用 `available_artifacts`；未生成入口时不因缺少 `AGENTS.md` 或适配表失败。
