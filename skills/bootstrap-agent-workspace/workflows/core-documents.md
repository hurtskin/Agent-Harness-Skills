# 核心工作区文档流程

> 仅在用户选择“核心工作区文档”时加载。

## 1. 项目识别

并行读取仓库结构、项目清单、README、入口、测试配置和已有 Agent 规则。确认：

- 项目名称、类型和目标
- scope 与 non-goals
- 用户角色、工作语言和部署形态
- 当前任务、活跃 Spec 和项目红线

有可靠证据则推断；否则结构化询问，不猜测。

## 2. 核心产物

按顺序生成或升级：

1. `.trae/rules/soul.md`：行为原则、文档先行、工具偏好和红线。
2. `AGENTS.md`：跨工具项目上下文、架构事实、当前任务、命令、Spec ↔ Code 导航、工具适配表。
3. `决策日志.md`：append-only 决策索引，不自动加载全文。
4. `.trae/rules/lessons-learned.md`：跨任务教训骨架，append-only。
5. 当前工具适配器要求的薄入口。

排期清单、changelog-rag 和 drift-check 不属于本流程；只有用户选择对应模块时才加载和生成。

## 3. soul.md 必备内容

- 项目身份、目标、scope、non-goals
- 不猜多问、先对齐后行动、最小改动
- 文档先于代码与 Spec 唯一事实源
- 沟通语言和代码引用格式
- 专用工具优先于终端命令
- Git、依赖、删除、迁移脚本和临时文件红线
- Bug 先报告、确认后修复
- 启动检查和文档职责边界

工具规则必须条件化：未安装 changelog-rag 时按关键词局部读取决策日志；未安装 drift-check 时使用项目现有测试/检查命令，不写不存在的强制命令。

## 4. AGENTS.md 必备段落

- 用户画像
- Agent 工具适配表
- 项目上下文
- 架构与数据流事实
- 当前任务
- 常用命令
- 文档目录树
- 决策变更流程
- AGENTS.md 自身变更日志

工具适配表至少记录：工具、自动加载入口、状态、来源、最后确认日期。

## 5. 决策日志骨架

每条决策保持 3–5 行索引：版本、日期、关联 Spec、变化程度和摘要。详细设计留在 Spec，不复制正文。

若未启用 changelog-rag，`AGENTS.md` 应写“按关键词和局部范围读取决策日志”，不得声称 MCP 工具存在。

## 6. lessons 骨架

只建立职责说明和稳定编号约定，不预填未经项目实践验证的教训。新增内容 append-only，不重排既有锚点。

## 7. 文档先行流程

1. 定位相关 Spec、决策和教训。
2. 读取现状，列出“文档现状 / 计划变化”。
3. 先更新文档并等待用户确认。
4. 严格按文档修改代码。
5. 运行用户已选择且实际安装的验证工具。
6. 回写决策、目录树和 lessons。

## 8. 升级策略

已有文件时先读取，默认只补缺失段落。若旧文档含工具硬编码，而用户此次未选择该工具，应改成条件化说明，不得保留失效命令。
