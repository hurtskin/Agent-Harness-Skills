# 核心工作区文档流程

> 仅在用户选择“核心工作区文档”时加载。

## 1. 项目识别

并行读取仓库结构、项目清单、README、入口、测试配置和已有 Agent 规则。确认：

- 项目名称、类型和目标
- scope 与 non-goals
- 用户角色、工作语言和部署形态
- 当前任务、活跃 Spec 和项目红线

有可靠证据则推断；否则结构化询问，不猜测。

## 2. 核心产物

按顺序生成或升级：

1. `.trae/rules/soul.md`：P0 稳定行为原则和安全红线。
2. `AGENTS.md`：P0 短导航与当前工作入口，索引 P1/P2 事实源。
3. `决策日志.md`：P2 append-only 决策索引，不自动加载全文。
4. `.trae/rules/lessons-learned.md`：P2 跨任务教训骨架，append-only，命中相关问题时读取。
5. 当前工具适配器要求的薄入口。

排期清单、changelog-rag 和 drift-check 不属于本流程；只有用户选择对应模块时才加载和生成。

## 3. soul.md 必备内容

soul 是 P0 规范源，只保留跨多数任务稳定成立、缺失会导致错误执行的原则：

- 项目身份、目标和不可越过的 scope / non-goals 边界摘要
- 不猜多问、先对齐后行动、最小改动
- 文档先于代码与 Spec 唯一事实源
- 沟通语言和代码引用格式
- 专用工具优先于终端命令
- Git、依赖、删除、迁移脚本和临时文件红线
- Bug 先报告、确认后修复
- 启动时从 `AGENTS.md` 获取当前入口，并按需读取 P1/P2 文档

不得在 soul 中堆放当前任务、详细架构、命令大全、决策历史、教训正文或客户端重复规则。工具规则必须条件化：未安装 changelog-rag 时按关键词局部读取决策日志；未安装 drift-check 时使用项目现有测试/检查命令，不写不存在的强制命令。

## 4. AGENTS.md 必备段落

AGENTS 是短导航，不是项目知识全文。优先使用表格和路径清单，保留：

- 最小项目定位与用户/协作约定
- 当前任务、活跃 Spec 和下一步入口
- 常用验证命令
- P1 文档索引：架构、数据流、活跃 Spec、排期等路径及读取条件
- P2 文档索引：决策日志、lessons、归档 Spec 的检索方式
- Agent 工具适配表
- AGENTS.md 自身变更日志

详细架构与数据流正文应留在对应 Spec/架构文档；历史任务、完整决策和教训不得回填到 AGENTS。工具适配表至少记录：工具、自动加载入口、状态、来源、最后确认日期。

## 5. 决策日志骨架

每条决策保持 3–5 行索引：版本、日期、关联 Spec、变化程度和摘要。详细设计留在 Spec，不复制正文。

若未启用 changelog-rag，`AGENTS.md` 应写“按关键词和局部范围读取决策日志”，不得声称 MCP 工具存在。

## 6. lessons 骨架

只建立职责说明和稳定编号约定，不预填未经项目实践验证的教训。新增内容 append-only，不重排既有锚点。

## 7. 文档先行流程

1. 定位相关 Spec、决策和教训。
2. 读取现状，列出“文档现状 / 计划变化”。
3. 先更新文档并等待用户确认。
4. 严格按文档修改代码。
5. 运行用户已选择且实际安装的验证工具。
6. 回写决策、目录树和 lessons。

## 8. 升级策略

已有文件时先读取，默认只补缺失段落。若旧文档含工具硬编码，而用户此次未选择该工具，应改成条件化说明，不得保留失效命令。
