## 背景

- 既有 AGENTS.md 协作原则6 条过于松散，缺硬约束：「不猜测；…只做…最小改动」/「Bug 先报告…修复」等条目对 Bug 诊断期行为、契约侧文件触碰、改动面边界未做硬性规定——导致模型在 Bug 任务中容易直接动手修代码，或借修 Bug 之名重写其它模块。
- 本次按用户明确授权覆盖原三条对应原则，落地新版 4 条核心 + 4 条嵌套硬约束。

## 决定

1. **AGENTS.md 协作原则章节** 改写（**覆盖**非追加）：
 - **不猜多问**：有歧义先问，不臆测数据字段、路径或用户意图
 - **先对齐后行动**：改动前先展示方案/文档差异并等待确认；Bug 处理先报告根因与证据，确认后再修复
 - 嵌套：**Bug 任务强制三段式**（诊断只读 → 等用户确认 → 实施）+ **禁止顺手优化**
 - **最小改动**：只改任务要求的部分
 - 嵌套：**改动面自检清单**（提交前过一遍：文件/函数是否在授权范围、有无新增 helper/class/配置、是否动非失败路径）
 - **文档先于代码**：业务/架构/接口/行为规则变更必须先改 Spec 再改代码
 - 嵌套：**诊断阶段禁动契约侧**（`specs/`、`decisions/`、`AGENTS.md`、`BACKLOG.md`、README）
 - 保留：路径成对 L0 / Correctness 变更门 / drift-inventory / 专用工具优先 / 每次会话从 AGENTS 获取入口。
2. **Bug 任务三段式编号修订**：用户给的原文 Bug 三段式编号为「(1)(2)(4)」缺 (3)——已纠正为 (1)(2)(3)；如有用户原意是 (1)(2)(4)，需另开会话澄清。
3. **同步 skill 模板措辞**（避免下游文档与顶层原则脱节）：
 - `workflows/core-documents.md` §3 协作原则章节「常规条目」第1/2/4 条改写，把新原则全部展开进模板生成的消费者 AGENTS.md 协作原则章节；保留「专用工具优先」/「每次会话从 AGENTS 获取入口」两条。
 - `workflows/core-documents.md` §1「协作模式」与 §2 段落把「不猜测」统一改为「不猜多问」。
 - `COMMON.md` §5 项目上下文识别「有证据则推断；无证据则询问，不猜测」改为「…不猜多问」。
4. **不动** `skills/task-handoff/SKILL.md`「不猜测」字样——该处是「状态文件损坏时是否合并」的特定上下文，与协作原则「不猜多问」语义不同。
